# Contributing to CareerLaunch

## Before implementation

The team will confirm the technology stack, architecture, responsibilities, and first-sprint tasks during the Saturday meeting. Do not treat the preserved dashboard prototype as the final architecture.

## Branch workflow

1. Update your local main branch.
2. Create a new branch from main.
3. Make one focused change on that branch.
4. Run the agreed tests and review your changed files.
5. Push the branch and open a pull request.
6. Ask at least one teammate to review the pull request before it is merged.

Suggested branch names:

- **feature/application-tracker**
- **feature/authentication**
- **feature/employer-contacts**
- **fix/short-description**
- **docs/short-description**

## Commit messages

Use short action-oriented messages, for example:

- Add application status model
- Create login form validation
- Document local database setup

## Pull requests

Each pull request should explain:

- What changed
- Why the change is needed
- How it was tested
- Any screenshots or setup changes
- Any follow-up work that remains

Do not commit passwords, API keys, access tokens, personal data, generated build output, or dependency folders.
